# 28. REAL BROWSER LIMITATION — IMPORTANT

DO NOT IMPLEMENT A FAKE "READ ANY HTML" ENGINE.

An ordinary Android application cannot universally execute:

document.querySelector()

inside another application's private Chrome page DOM.

Chrome's internal DOM is not simply exposed to another app.


Therefore:

Android implementation should evaluate, in this order:

1. Android Autofill Framework
2. Appropriate Android accessibility-tree interaction
3. Controlled WebView bridge when the application owns the WebView


Android Autofill is specifically designed for services that fill views in other apps and is available from Android 8.0/API 26. 


AccessibilityService can retrieve accessibility window content when the service declares the relevant capability and can interact with accessible nodes, but this is NOT equivalent to unrestricted raw HTML/DOM access.


The developer must never claim:

"Universal HTML access"

unless the actual integration provides it.

### सबसे जरूरी genuine points

1. **तुम्हारा Auto Fill वाला requirement सही architecture में possible है**, लेकिन “हर Chrome website का raw HTML पढ़ो” को literal requirement मत बनाओ। Android का Autofill Framework दूसरे apps के views को fill करने के लिए बना है, जबकि AccessibilityService accessible window/node content के साथ काम करता है। ([Android Developers][1])

2. **Floating button का Android version possible है**, लेकिन overlay permission और service lifecycle properly implement करना पड़ेगा। Android 8+ में `TYPE_APPLICATION_OVERLAY` और `SYSTEM_ALERT_WINDOW` relevant हैं। ([Android Developers][3])

3. **Android 14+ में background service को “बस हमेशा चलता रहेगा” मानना गलत है।** Foreground-service type/permission और background-start restrictions लागू हैं। ([Android Developers][4])

4. **Google Play पर AccessibilityService वाला हिस्सा खास ध्यान से करना होगा।** अगर app accessibility tool नहीं है, तो disclosure/consent और Play Console declaration requirements लागू हो सकती हैं। ([Google Support][2])

5. **iOS को Android जैसा floating overlay मत बनाना।** iOS में सही रास्ता system-supported AutoFill/extension architecture है; Apple का Credential Provider Extension इसी तरह के AutoFill integration के लिए है। ([developer.apple.com][5])

और सबसे महत्वपूर्ण तुम्हारे performance goal के लिए architecture यही रहेगा:

**Aadhaar/PAN upload → OCR + parsing सिर्फ एक बार → encrypted local JSON → बाद में website पर Auto Fill → JSON से direct matching/fill.**

इससे website खोलते समय दोबारा Aadhaar image पढ़ने या OCR करने की जरूरत नहीं पड़ेगी।

# FINAL FLOATING SMART FILL — ANDROID IMPLEMENTATION SPECIFICATION

## Project Context

Existing application:

- React Native
- Expo
- TypeScript
- Secure Vault
- Local-first document storage
- Local OCR
- Deterministic document parser
- Encrypted local JSON/profile storage
- Smart Fill functionality

DO NOT migrate to Flutter.

This task is ONLY for the final Floating Smart Fill interaction and lifecycle.

Do not redesign the entire application.

---

# 1. PRIMARY OBJECTIVE

When the user starts Smart Fill and minimizes the application:

THE FLOATING SMART FILL CONTROL MUST REMAIN VISIBLE.

It must NOT disappear merely because:

- The app is minimized
- User presses Home
- User switches to Chrome
- User opens another supported browser
- User switches between applications

The floating control must remain active until:

1. User explicitly presses CLOSE on the floating control, OR
2. User returns to the main application and disables Smart Fill.

ONLY TWO ACTIONS.

Do not add unnecessary third/fourth buttons.

# 23. SERVICE RECOVERY

DO NOT silently pretend that Smart Fill is still active.

```text

```
